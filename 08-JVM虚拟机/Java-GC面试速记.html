理解 GC为什么需要看个例子面试怎么说
01

GC 是什么？

GC = Garbage Collection，垃圾回收。
由 JVM 自动回收不再可达的对象占用的内存，让空间可以再次使用。

先记两个词：JVM 是运行 Java 程序的虚拟机；堆是存放对象的主要内存区域，也是 GC 的主要工作区域。

“垃圾”不是没用的代码。这里说的是：程序沿着有效引用，已经找不到的对象。
02

为什么需要 GC？

内存有限，要重复利用

程序不断创建对象。旧对象用完后，如果内存一直不释放，新对象最终就没有空间可用了。

交给 JVM，减少手动管理出错

开发者不用逐个释放对象内存，减少忘记释放、重复释放等问题，更专注于业务逻辑。

但 GC 不是免费的：它会消耗 CPU，某些阶段还会暂停应用线程（STW）。自动回收，也不代表内存永远够用。

03

04

面试时，30 秒这样说

GC 是 Java 的自动垃圾回收机制，主要负责回收堆中不再可达的对象占用的内存。

因为内存有限，程序又会不断创建对象，所以需要回收不用的空间，让它能被再次利用；同时，自动回收可以减少手动管理内存的错误。

JVM 主要通过可达性分析判断对象是否需要保留。不过 GC 有性能开销，也不能保证程序不会出现内存泄漏或内存溢出。

记忆顺序：自动回收 → 内存复用 → 可达性 → 有成本、有边界

合上答案，自测一句：有 GC，为什么还会内存泄漏？

因为业务已经不用的对象，可能还被集合等长期引用。GC 看到它仍可达，就不能回收。例如长期存活的缓存不断加入对象，却从不清理。

最后，别答错这 3 个点

设成 null，就会立刻回收吗？

不会。设成 null 只断开一条引用，其他引用可能还在。即使对象已经不可达，也要等到适当的回收时机。System.gc() 也只是请求，不能保证立即回收指定对象。

有 GC，就不会内存溢出了吗？

不是。仍被引用的对象太多，或堆空间不够，都可能导致 OutOfMemoryError（OOM，内存不足错误）。内存泄漏是“不用的对象仍被意外持有”；内存溢出是“分配内存无法满足需求”。泄漏可能导致溢出。

文件、数据库连接也交给 GC 吗？

不能依赖 GC 及时释放这些资源。文件流、数据库连接应及时关闭，适用时用 try-with-resources。GC 回收对象内存，不能替代资源生命周期管理。
